# Smoke Burger

Учебный многостраничный сайт ресторана быстрого питания на React и Vite.

## Запуск

Установите Node.js, затем в папке проекта выполните:

```bash
npm install
npm run dev
```

Для production-сборки используйте `npm run build`.

## Возможности

- Главная страница, меню и контакты с переключением русского и казахского языков.
- Каталог блюд и цены перенесены с предоставленных скриншотов меню; карточки блюд содержат описания и приблизительную калорийность.
- Настройка доступных вариантов блюда, добавление сыра, соуса и картофеля фри, комментарий к позиции.
- Корзина сохраняется в браузере. Перед оформлением заказа покупатель указывает контакты, проверяет состав и итог, затем подтверждает обработку данных. Без онлайн-оплаты заказ отправляется через WhatsApp.
- Контакты ресторана: +7 (777) 040-34-07, Гульдала, ул. Кичикова, 4Б/1; Пн–Вт и Чт–Вс с 11:00 до 22:00, среда — выходной.
- При подключённом Supabase заказы хранятся в общей базе, а сотрудники ведут их статусы в `/admin`. С включённой интеграцией Freedom Pay посетитель оплачивает заказ на защищённой странице провайдера, а ресторан получает заказ только после подписанного серверного подтверждения платежа. В демо-режиме заказ передаётся через WhatsApp.
- Instagram-галерея использует фрагменты скриншотов меню, предоставленных для учебного проекта: https://www.instagram.com/smoke.burger.kz/
- Для карточек меню взяты иллюстративные фотографии из публичных каталогов [Maki Food в Wolt](https://wolt.com/en/kaz/almaty/restaurant/makifoodshemyakin) и [Dodo Pizza](https://dodopizza.kz/en/almaty). Это реальные фотографии блюд других ресторанов, а не фотографии Smoke Burger; перед коммерческой публикацией замените их собственными или получите разрешение правообладателя.

## Структура

- `src/main.jsx` — страницы, корзина и форма настройки блюда.
- `src/data.js` — каталог блюд, цены, описания и калорийность.
- `src/i18n.js` — тексты интерфейса на русском и казахском языках.
- `src/business.js` — контактные сведения ресторана.
- `src/admin.jsx` — панель сотрудников, редактор меню, акций и модерация отзывов.
- `src/backend.js` — Supabase REST Auth/Data API и локальный режим для демонстрации.

## Панель сотрудников и общие данные

Без настройки Supabase сайт работает в демонстрационном режиме. Изменения из `/admin` сохраняются только в текущем браузере и не видны клиентам с других устройств.

Для общей панели:

1. Создайте проект Supabase и по порядку выполните миграции `202611240001_store_admin_reviews.sql`, `202611240002_orders.sql` и `202611240003_freedompay.sql` из папки `supabase/migrations` в SQL Editor.
2. Выполните `npm run seed:supabase`, затем скопируйте содержимое `supabase/seed.sql` в SQL Editor, чтобы загрузить меню.
3. В Supabase Auth создайте сотруднику пользователя с email и паролем. В SQL Editor добавьте его UUID в `public.staff_users`:

   ```sql
   insert into public.staff_users (user_id) values ('UUID_СОТРУДНИКА');
   ```

4. Скопируйте `.env.example` в `.env.local`, укажите Project URL и publishable/anon key из настроек Supabase, затем перезапустите Vite.
5. Откройте `/admin` и войдите с созданной учётной записью. Секретный/service-role ключ нельзя помещать в браузер или публиковать.

Для production-сборки задайте те же две переменные в настройках сборки хостинга, затем пересоберите сайт. Не добавляйте `.env.local` в Git.

Цены, описания и наличие после подключения хранятся в Supabase и доступны на всех устройствах. Отзывы попадают в очередь и появляются на сайте после одобрения. Условия, сроки и активность акций редактируются в панели и показываются посетителям. Заказы поступают в `/admin`, а список обновляется автоматически, пока открыта вкладка заказов.

### Подключение онлайн-оплаты Freedom Pay

Для реальных платежей ресторану нужны активный договор и merchant ID/платёжный секрет Freedom Pay. Не добавляйте платёжный секрет или Supabase service-role key в `.env.local`, клиентскую сборку, GitHub или чат.

1. После применения миграции выше задайте секреты Supabase на сервере (подставьте свои значения в локальном терминале, не коммитьте их):

   ```bash
   supabase secrets set FREEDOMPAY_MERCHANT_ID=... FREEDOMPAY_PAYMENT_SECRET=... APP_PUBLIC_URL=https://ваш-домен.kz FREEDOMPAY_TEST_MODE=true
   ```

   Перед приёмом реальных платежей отключите тестовый режим значением `false` и убедитесь, что Freedom Pay активировал live-доступ.
2. Разверните серверные функции:

   ```bash
   supabase functions deploy create-freedompay-payment
   supabase functions deploy freedompay-result
   supabase functions deploy payment-status
   ```

   Supabase Edge Functions используют проектные переменные `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`; ключ service-role должен оставаться только в среде Supabase.
3. В `.env.local` задайте `VITE_ONLINE_PAYMENT_ENABLED=true`, оставив включёнными `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`, затем пересоберите и опубликуйте сайт. Пока флаг выключен, оформление продолжает работать через WhatsApp.
4. Сначала проверьте тестовую оплату в аккаунте Freedom Pay. После возврата на сайт статус считается оплаченным только по серверному callback `freedompay-result`, а не по странице возврата клиента.

Интеграция использует размещённую Freedom Pay платёжную страницу: данные карты вводятся у провайдера. Перед включением коммерческого приёма платежей настройте тестовый режим и URL возврата в merchant-аккаунте, затем выполните end-to-end проверку с аккаунтом ресторана. Callback результата передаётся в каждом платёжном запросе на Supabase Edge Function. Формат платёжной страницы и подписанных callback сверяется с [официальной документацией Freedom Pay](https://docs.freedompay.kz/create-payment-9890787e0) и [описанием уведомления о результате](https://docs.freedompay.kz/result-notify-12007677e0).
